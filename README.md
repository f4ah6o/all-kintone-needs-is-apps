# All kintone Needs is Apps — 項目別取込の検証版

kintone の運用環境にある設定、ユーザー、組織を読み、設定項目を kintone のフィールドに格納する PC 向けの検証版です。設定元のアプリ、ユーザー、組織は変更しません。設定変更のコマンド側は未実装です。

## 導入時のアクセス権

**テンプレートから作成した直後は、全員に閲覧・追加・編集・削除が許可された状態で自動公開されます。** レコードを取り込む前に、アプリの設定 > アクセス権 > アプリで Everyone の全権限を外し、アプリ作成者の権限を残して「アプリを更新」してください。更新後、運用環境の設定を確認します。

本検証版は取込直前にアプリのアクセス権を取得し、作成者以外に何らかの権限が許可されている場合は取込を中止します。アプリ管理権限がなくアクセス権を確認できない場合も中止します。これは現在の検証用制約であり、複数の管理者に閲覧を許可する運用には対応していません。カスタマイズの適用範囲もアプリ管理者のみです。

取り込む内容には個人情報や設定の権限情報が含まれます。アプリ管理者・システム管理者のアクセス、保持期間や削除、バックアップを含めて運用してください。アプリ側の権限を広げると、作成済みレコードを閲覧できる範囲も広がります。取込時の確認は継続的な監視ではありません。

## 導入と操作

1. `kintone-template-expanded.zip` をアプリストアの「テンプレートファイルを読み込んで作成」から読み込みます。
2. 上記のとおり権限を制限し、アプリを更新します。同一環境への再導入では、フィールド、一覧、JavaScript、CSSが再現されました。レコードは含まれませんでした。
3. PC のレコード一覧で「アプリ」「ユーザー」「組織」を選び、対象を選択して「項目ごとにレコードへ取り込む」を押します。操作ごとに取得し直して追加します。検索欄は取得済み一覧の名前・コード・IDを絞り込みます。
4. 完了後に一覧を再読み込みすると「設定レコード」一覧に取得元、設定名、アプリ設定リビジョン、取得日時などが表示されます。取込IDで同じ取込に属するレコードを確認できます。

旧形式の JSON レコードは変更・削除しません。新形式に自動変換もしません。

## データの構造

- 一般設定は設定のレコード、フィールドはフィールドごとのレコード、一覧は一覧ごとのレコードとして格納します。フォーム配置は行、アプリのアクセス権は優先順位ごとに記録します。各APIの取得成功・失敗も記録します。
- ユーザーは1人ごと、組織は1組織ごと、所属はユーザーが所属する組織ごとに記録します。選択肢や入れ子の内容は、同一取込ID・種類・取得元ID・設定名を共有する別レコードに分け、「設定内の位置」「親の位置」「並び順」で関係を示します。kintone の関連レコード一覧フィールドによるリンクはまだありません。
- 値は `項目：code`、`項目：label` 等の対応するフィールドに入ります。現段階では各値を文字列として格納し、真偽値も `true` / `false` の文字列です。null の項目名は別フィールドに記録します。未対応のプロパティを検出した設定は未対応として記録し、その設定の値は保存しません。他の設定は保存します。
- アプリ設定の各APIから返されたリビジョンを各レコードに保存し、取得の最後にも再確認します。リビジョンの不一致、欠落、最終確認の失敗がある場合、そのアプリの取込を開始しません。取得済みの最新リビジョンとの差分比較や自動更新はありません。User API には同じアプリ設定リビジョンがないため、ユーザー・組織のリビジョン欄は空です。
- 取込は追加方式です。1回のAPIで100レコードずつ登録します。途中で失敗した場合、登録済みの件数と取込IDを表示します。既に登録された分は自動では取り消されず、再実行すると重複します。

## 取得範囲と認証

アプリ設定は一般設定、フィールド、フォーム配置、一覧、グラフ、プロセス管理、アプリ・レコード・リマインダーの通知、アプリ・レコード・フィールドのアクセス権、アクション、プラグイン一覧の14種類です。取得失敗と未対応を区別し、権限不足か断定できない失敗はそのまま表示します。アプリ一覧は実行者が閲覧または追加できる公開アプリに限られます。アプリのアクセス権の取得にはアプリ管理権限が必要です。各APIで権限が異なります。

JavaScript / CSS の設定、Webhook、APIトークン、カテゴリー、プラグインの個別設定などは本版の取得対象外です。API が公開されていないと断定するものではありません。設定に秘密情報が含まれる可能性があるため、対象を広げる際は保存先と閲覧権限を別途設計してください。

ユーザー・組織・所属はUser APIを使用します。取得する情報と項目の公開範囲は実行ユーザーに依存し、ゲストユーザーのユーザー・所属取得には対応していません。kintoneにログインしたユーザーのセッションを使い、資格情報をソースや設定に埋め込みません。

参考：[アプリ一覧](https://cybozu.dev/ja/kintone/docs/rest-api/apps/get-apps/)、[一般設定とリビジョン](https://cybozu.dev/ja/kintone/docs/rest-api/apps/settings/get-general-settings/)、[フィールドとリビジョン](https://cybozu.dev/ja/kintone/docs/rest-api/apps/form/get-form-fields/)、[ユーザー](https://cybozu.dev/ja/common/docs/user-api/users/get-users/)、[組織](https://cybozu.dev/ja/common/docs/user-api/organizations/get-organizations/)、[所属](https://cybozu.dev/ja/common/docs/user-api/users/get-users-organizations/)。

## 検証と残る制約

2026-11-12 の同一テナントで、元アプリの設定31レコード、ユーザー1人の情報、検証アプリ自身の設定784レコードを取り込みました。一般設定・フィールド等のリビジョンと個別フィールドの表示、100件単位の複数回登録を確認しました。新テンプレートを別アプリへ再導入し、初期の広い権限では取込が0件で止まり、権限を制限した後に31件の取込が完了しました。動作テスト画面からの取込も0件で停止します。動作テスト画面から通常のレコードAPIを実行すると運用環境に影響するためです（[公式仕様](https://cybozu.dev/ja/kintone/docs/js-api/overview/kintone-js-api-overview/)）。

拡張版では、検証元アプリの14種類の取得と最終リビジョンの一致、51レコードの追加（取得失敗0件・未対応0件）を実環境で確認しました。多くの追加設定は空の状態です。動作テスト画面からの保存は0件で中止されました。テンプレートに含まれる3つの JavaScript と CSS はローカル版と一致しました。同一テナントに再導入し、初期権限では取込が0件で止まり、作成者のみに制限後は51件を保存できました。アプリ更新直後に一覧読み込みエラーが1回発生しましたが、再読み込み後に既存レコードを表示できました。

未検証：所属や役職に実値があるケース、組織の実データ、追加した設定に値が入っている実データ、取得元に対する権限不足、100件を超えるアプリ・ユーザー・組織の一覧取得、別テナント、プラグイン設定、ゲストスペース、モバイル。対象外のアプリ設定も多数あります。アプリやユーザーは1件ずつ選んで取り込み、一括同期は未実装です。レコードは通常の権限で編集・削除でき、改ざん防止の監査ログではありません。

ローカル試験：`node --test model.test.js query.test.js` 11件 PASS。`node --check` で `model.js`、`query.js`、`customize.js`、`setup.js` を確認。模擬APIと変換の試験であり、実際の権限差を代替しません。
